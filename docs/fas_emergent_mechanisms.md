# FAS 涌现机制盘点（fas_emergent_mechanisms.md）

> 认知架构重评估 · 文档 3/7
> 回答重评估提纲问题 (3)(4)：当前已经出现了哪些"意外机制"？哪些值得保留？
> 涌现机制的定义：**不是任何人（论文或开发者）预先设计的，而是在运行/开发过程中自然形成、并开始承担认知职能的机制**。
> 判定标准：①设计文档/论文里找不到它的设计记录；②它已经在数据或行为中留下可验证的痕迹；③删掉它会让某个行为退化。
> 原则九（"不要因为某机制'不在论文里'就默认它必须删除"）适用于本文全部条目。

## 二、值得保留的涌现机制（详细论证）

### 2.1 焦点事件指针（当前焦点事件 节点）

**它是怎么涌现的**：MEMORY_EXTRACT 落地后发现，"今天已经是出发的日子了"这类延续陈述需要知道"当前在经历哪件事"，于是为图添加了一个 self 空间的 infrastructure 节点，用 指向 边锚定头部事件。没有任何设计文档预先规划它。

**为什么说它是涌现而非设计**：它的价值不是"功能列表里的一项"，而是**它改变了其他机制的行为**——MEMORY_EXTRACT 的第 5 条规则（parent_event 填已有事件名）完全建立在指针存在的前提上。这是"一个图结构催生另一个图结构用法"的涌现形态。

**涌现潜力**：如果指针本身参与扩散（当前只是被动读取），它会成为"心理时间线上'当下'的位置感"——LSTM 时代的 psi-agent 与 working self（Conway）的图内对应物。V2 建议给指针一条低权重自激活边，让它随对话自然迁移而非代码改写。

### 2.2 事件框架的自发层级化

论文 §3.4 设计了层级化事件（头事件+子事件+时间顺序边），但"哪个事件成为头、新陈述如何归入既有事件"没有任何算法规定——这完全由 MEMORY_EXTRACT 的 LLM 按模板第 5 条自己判断。数据验证：远方之行 有 3 个子事件、7 条 时间顺序 边，形成了论文设想的叙事结构。

**这是全系统最成功的一次涌现**：机制只给了模板约束（事件节点必须存在、用户连事件不连实体），组织结构完全在运行中形成。它证明了 FAS 的核心论点（给图结构和扩散规则，行为自己长出来）在记忆领域是成立的。

**保护条件**：不要把"事件归类"逻辑写成代码 if-else（比如"同一天的事件自动合并"）。归类错误应该通过反思/后续陈述修正，而不是规则裁决。

### 2.3 词汇化短语表的自我积累

compound_phrase_handler 的设计动机只是省 LLM 调用，但它的运行方式意外符合最终愿景：**规则只在第一次判定时使用，判定结果沉淀为可复用资源，之后完全靠查表**。这正是"越来越少的硬编码规则产生越来越丰富的行为"的字面实现——每处理一个新短语，系统对这类短语的规则依赖就永久减少一分。

**扩展方向**：当前它只服务好奇心过滤。复合短语判定结果应该成为语言层的常规输出（所有输入先查表再走 LLM 解析），短语表的增长率本身就是"语言能力成长"的量化指标——这是可以写进论文验证章节的涌现证据。

### 2.4 UnknownObject 与好奇心/驱力的意外联动

vision 桥接为未命名对象建 UnknownObject 节点（数据中 8 个），CuriosityDrive 统计图内未知信号时把 UnknownObject 计入。**设计上这两者从未被规划为一条通路**，但它们实际上形成了：感知发现未知 → 图内未知节点 → 驱力激活 → 好奇提问。

这是"万物皆图红利"的第一个实例：当感知产物和动机统计都以节点形式存在于同一图上，它们**自动**发生了连接，不需要任何胶水代码。V2 的好奇心重构（未知节点激活驱动提问）应该以这条已存在的通路为骨架，而不是另起炉灶。

## 三、意外沉积物（涌现的反面：机制运行产生的垃圾）

> 涌现机制评估必须双向：系统不仅涌现了好的结构，也沉积了垃圾。垃圾之所以是"意外机制"，因为它们也在改变系统行为——通过稀释激活、污染 Top-k、扭曲驱力统计。

### 3.1 回答记录_ 节点（52 个，图内最大节点类）

每轮回答自动建 回答记录_N + 源自 边。本意是过程可追溯（论文 §8.6），实际效果：

- **稀释**：52 个记录节点都是低连接度孤立节点，激活注入时挤占 FAISS 召回与 Top-k 位置；
- **扭曲**：反思引擎读图统计"最近活动"时，回答记录的数量远超真实经历事件，反思语料被对话行为淹没；
- **语义空洞**：记录节点对扩散毫无贡献（没有下游边），是纯激活黑洞。

**处理**：不是删除机制，是降格存储——回答过程应该写入对话日志（已有 chat_log，且定位诚实），图内只保留有结构意义的部分（如 新知识边的证据引用，disposition 的 evidence 字段已这么做）。判据（vision 三问）：状态应该在图里吗？——回答文本不是认知状态，是认知活动的**痕迹**；痕迹归日志。

### 3.2 思考_ 节点（22 个，label 错误）

内部思考以节点入图，但被标为 declarative-episodic/episodic 空间——思考是**认知活动**不是**经历**，应属 cognitive 空间。此外思考节点与驱力/情绪节点一样参加了扩散，把"我当时在想什么"当成了事实知识传播。

**处理**：存量迁到 cognitive 空间；增量反思——内部思考是否需要节点化本身存疑（它更像 disposition evidence 与反思语料的原料）。V2 中思考产物的主要去向应是反思引擎的观察缓冲，节点化仅在思考确实形成新概念时发生。

### 3.3 两阶段扩散 hack 的惯例化

好奇心注入后需要立即重新扩散，最初实现是临时改写 config["max_depth"] 再恢复。补丁本身可以理解，但它后来成了"需要立即重扩散时就这么干"的惯例解法——流程控制借道 config 完成了对动力学的直接干预。

**处理**：删除。扩散引擎应提供显式的分阶段 API（注入批 A→扩散→注入批 B→扩散），让"多阶段认知循环"成为引擎的一等公民而不是 config 体操。

## 四、涌现机制的培育条件（V2 设计约束）

从上述正反两方面经验，提炼出 V2 必须遵守的"涌现培育法则"：

1. **机制给约束，结构自己长**：事件框架的成功（§2.2）证明——模板约束输出形状，组织决策交给运行时判断。V2 的一切新机制（行为竞争、好奇心、参数调制）都应以此模式落地。
2. **图上的新节点类型会自动获得红利**：UnknownObject×Drive 的联动（§2.4）证明——在图上新增一类节点，它就会和现有统计/扩散自动连接。新增认知要素时应优先考虑"建节点类型"而非"建代码通路"。
3. **每次只沉淀可复用的判定，不沉淀一次性流程**：短语表（§2.3）是对的，两阶段 hack（§3.3）是错的。判据：这个沉淀下次遇到类似情形还会被用到吗？
4. **活动痕迹不进图**：回答记录（§3.1）的教训——图的职责是认知状态与结构，不是活动流水。追溯需求由日志满足，图内只保留影响未来认知的部分。
5. **定期用数据审计图的组成**：52 个回答记录、0 个倾向节点、0 个信念节点——这个分布本身就是系统健康度的直接诊断。V2 应把这个审计做成常规操作（一个统计脚本），而不是等到架构重评估才发现。
