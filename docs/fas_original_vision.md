## 一、FAS 最初想成为什么

### 1.1 它是对三个问题的架构回应，不是一个产品

论文绪论（novel.txt §1.1）明确指出 FAS 针对的是当前 LLM 智能体的三个架构性问题：

1. **事实性幻觉与知识更新困难** —— 参数化知识缺乏外显、可持续校验的真值锚点；
2. **上下文窗口有限导致记忆碎片化** —— 长周期交互中早期关键信息脱离注意范围，RAG 只做片段级检索、缺乏显式因果与时间组织的长时情景记忆；
3. **推理过程不可追溯** —— 输出以概率生成方式产生，决策依据难以外显，误差逐步累积。

因此 FAS 的原始定位是：**以统一知识图谱为表征载体、以激活扩散为核心动力机制的认知架构原型**，在"工程可实现性与认知合理性之间寻求折中路径"（§1.2）。

### 1.2 核心命题：认知 = 统一图结构上的连续动力学演化

论文 §1.3 的设计思想一句话概括：

> "认知过程可以被重新理解为统一知识结构上的连续动力学演化，而不必完全建模为一系列离散的符号操作或模块调用流程。"

由此推出三个可检验的架构主张：

- **注意力焦点不是被分配的，而是涌现的**："注意焦点的形成，未必必须依赖一个显式、中心化的调度器，也可能源于知识网络内部激活动力学的自然演化"（§1.2）；FAS "尽量减少额外中心化控制器在焦点形成中的主导作用"（§2.3.2）。
- **行动选择是注意竞争的延续**："当某一 Action 节点的激活度超过阈值 θact 时，它进入执行队列。这意味着，行动选择在结构上被视为注意竞争的延续，而不是与注意分离的第二套控制系统"（§8.5）。
- **学习与认知是同一过程**："系统并非先完成思考、再离线学习，而是在思考过程中持续修正其知识结构与连接强度"（§6）。

### 1.3 LLM 的原始定位：受约束的结构归纳器

论文 §8.8.1 是整个审计中最关键的一节，原文标题即"**LLM 在架构中的角色边界：从生成中心到结构映射接口**"：

- LLM "更主要地被定位为一种结构映射与语义组织接口"，完成"从非结构化输入到结构化事件框架、从候选语义片段到图谱可写入表示之间的转换"；
- FAS 对 LLM 的使用"更接近一种'受约束的结构归纳器'，而非'开放式生成中心'"；
- LLM 的输出空间受强约束："它需要输出的是事件框架、关系候选、参数实例或局部结构补全结果，而不是无限制的自然语言续写"；
- LLM 输出"需要进一步接受图结构写入规则、节点类型约束、关系一致性检查以及后续可追溯传播机制的检验"。

注意一个容易被误读的细节：论文中 LLM 也参与生成（Top-k 候选 → LLM 组装事件框架作为认知焦点，§5.1.4），但其生成物**仍然是结构（事件框架），不是面向用户的自由文本**。面向用户的自然语言输出在原始论文中并不存在——论文实验的"输出"是 `Answer(AI)`、`Answer(Fruit)` 这类行动执行。

### 1.4 原始实验验证的闭环

论文第 7 章验证的最小闭环是：

```
自然语言输入 → 三元组抽取写入图谱 → 注入激活 → 扩散+衰减
→ Top-k 注意候选集 → 检测 Action 节点 → 执行脚本 → 结果回写图谱
```

三个验证任务（§7.4）：基础动作触发（Who are you → Answer(AI)）、未知概念检测与图谱扩展（Apple → CreateUnknownNode + SearchFromWiki）、知识驱动决策（What is Apple → Answer(Fruit)）。

**这组任务里没有任何一个的输出是"聊天回复"。** "对话能力"是 2026 年开发期后加的需求，不是原始愿景的组成部分。

## 二、FAS 最初要做什么（原始功能清单）

以下每项均可在论文中找到明确段落，属于**最初设计**：

| # | 机制 | 论文出处 | 要点 |
|---|------|---------|------|
| 1 | 统一知识图谱 | §3 | 概念/实体/事件/动作/规则/情绪/性格/意图/预期全部为节点+加权有向边；陈述性（语义+情景）与程序性记忆共存一图 |
| 2 | 激活扩散 | §5.1 | Δa = a(u)·(w+r)；衰减 λ；终止条件 Dmax/θ；Top-k 注意候选集；关系语义同步激活 |
| 3 | 认知焦点 | §5.1.4 | Top-k + 局部连接结构 → LLM 组装为事件框架 = 当前认知焦点 |
| 4 | 事件框架 | §3.2 | 事件中心节点 + 论元槽位（Agent/Patient/Action/Time/Location/Attribute）+ 映射边锚定到全局实体 |
| 5 | 层级化事件 | §3.4 | 头部事件框架 + 子事件 + 时间顺序/因果关系边，跨事件通过共享实体耦合 |
| 6 | 自认知子图谱 | §3.3 | 系统信息、当前焦点事件框架、当前感知事件框架、前瞻性记忆节点、情绪与性格节点、**腺体/受体/激素节点**、**参数节点** |
| 7 | 情绪调制 | §3.3 | 激素节点激活强度 ≈ 情绪状态，调制全图扩散增益与传播方向 |
| 8 | 性格 | §3.3 | 性格 = 对情绪信号具有长期稳定调制作用的结构性偏置（改变情绪节点的响应阈值、衰减速率或影响系数），"逐步塑造系统稳定的认知风格与决策惯性" |
| 9 | 参数节点 | §3.3 | λ、β、k、θact、η 以参数节点存于图中，运行时取值 p(t) = clip(p0 + Σ α·a(m,t))，由情绪/动机节点连续调制 |
| 10 | 程序性记忆 | §3.5 | 函数代码驱动节点 + hasPolicy 强化学习策略驱动节点两类 |
| 11 | 行动执行 | §5.2 | 激活超 θact → 优先级行动队列（可动态重排）→ 执行 → 结果作为新节点回写 |
| 12 | 符号推理工具 | §5.2 | 事件框架 → 谓词三元组 → Prolog/facts → 高置信结论回写 + βlogic 推理链增强 |
| 13 | 目标/前瞻 | §5.2 | 目标事件框架低基线激活驻留图内，触发条件满足时获得激活增益上升为焦点 |
| 14 | 外部知识抽取 | §6.1 | LLM 抽取 (head,relation,tail,confidence)；按来源权威度赋初权；重复观测 δ 增量增强；**稀疏邻域触发外部知识查询** |
| 15 | Hebbian 经验强化 | §6.2 | w += ε·a(u)·a(v)，共同激活的连接获得微小即时增量——**论文中最核心的"学习"机制** |
| 16 | 反思学习闭环 | §6.3 | 行动结果编码为事件框架回写（含奖励值/成败标签/情绪评价节点），再激活时对相关行动/目标节点施加增益或抑制 |
| 17 | 情节缓冲器 | §4.1 | 多模态（视觉坐标+听觉方向）对齐整合 → LLM 归纳为事件框架；缓冲窗口由图内参数动态调节 |
| 18 | 可解释性 | §8.6 | 贡献集合 S(v) 记录激活来源，可输出传播链路，解释节点为何进入焦点 |

**论文中明确展望但标注"尚未实现"的**（§8.11）：GNN 消息传递作为可微动力层。这属于后续研究方向，不属于原始实现承诺。

## 三、哪些是计划外出现的（按时间线）

论文（2025-04）之后，系统在 2026 年的演化产生了大量论文中没有的机制。按来源分四类（对应审计要求的"最初设计/后续主动加入/工程补丁/LLM 需求"分类法，详见 fas_mechanism_audit.md）：

### 3.1 后续主动加入（有意识的设计决策，非论文原文）

- **对话能力本身**：`/api/nlp` 回答生成管线。论文没有面向用户的语言输出。
- **语言四层分类**：illocutionary_act（Searle 五类）/ dialogue_act（19 类）/ response_expectation（四级）/ suggested_reply_goals（14 种）——为"如何回应"而设的认知分类体系（2026-07）。
- **万物皆图原则的强化表述**：README 与审计报告把"一切认知活动走图谱扩散、不设旁路"上升为铁律，并为此设计了 社交互动/LLM回答/网络搜索 等基础设施节点。
- **好奇心引擎**（未知检测 → 知识缺口 → 好奇 → 提问 → 等待回答 → 知识完善）：论文只有"未知检测 → CreateUnknownNode + SearchFromWiki"的行动触发，好奇心作为**认知状态与提问行为**是后续设计。
- **Drive System / Action System**（Phase 3/4）：CuriosityDrive 等驱动力评估、COGNITIVE_CAPABILITIES 能力清单与 ActionIntent——论文中对应物只有行动队列。
- **Reflection Engine 与 Reflection Evolution（disposition）**：论文 §6.3 有反思闭环，但"6 问反思"、"情境-[激活]->行为 倾向边"、"candidate→stable 晋升"是 2026-08 的再设计，且 disposition 的动机（人格从经历中形成）与论文 §3.3 性格调制机制**方向一致但实现路径完全不同**（论文：性格调制情绪参数；实现：情境→行为边权强化）。
- **Self Model（信念/偏好/来源追踪）**、**能力注册表/发育阶段**、**Knowledge Pack 系统**、**FAISS 语义召回**、**网络搜索动作**。

### 3.2 工程补丁（为让系统跑起来而加，无认知含义）

`_fuzzy_match_node` 名称归并、`extra_attrs.aliases` 别名、回合间衰减+激活地板、INFRA_IDS 每轮过滤、json_mode 探测降级、MiMo max_completion_tokens 适配、重命名映射 rename_map、非教学 DA 门控、GBD/编码规避。

### 3.3 LLM 需求（因为用了 LLM 才需要的防线）

NLP_PARSE 重试、`_sanitize_result` 白名单校验、事件框架模板的 7 条规则细化、"None"/"null" 字符串归一、MEMORY_EXTRACT 元对话指令豁免。

### 3.4 无意演化成核心的

**`/api/nlp` 的 900 行单体函数**。论文的认知循环是"扩散→焦点→行动→回写"的抽象循环，实现中它变成了一个按编号阶段（0/0a/0a2/0b/0c/0d/0e/1/2a-pre/2a-pre.5/2a/2b/5）顺序执行的 if-else 流水线。这个函数没有对应任何论文机制，却成了 FAS 实际上的"认知循环"本身。**这是当前实现与原始愿景之间最大的单点偏差**（详见 fas_unwanted_mechanisms.md §1）。

## 四、FAS 明确不是什么

| 不是 | 证据 |
|------|------|
| 不是 LLM 智能体框架 | §8.8：LLM 智能体框架"系统状态、长期知识与执行结构之间缺乏统一的显式建模"，FAS 正是为此提供替代 |
| 不是以 LLM 为大脑的系统 | §8.8.1；FAS_IDENTITY："LLM 是你的语言接口，不是你的大脑" |
| 不是聊天机器人 | 审计报告 2026-07-28："FAS 不是聊天机器人，是认知系统"；论文实验无聊天输出 |
| 不是 RAG 系统 | §1.1 明确批评 RAG "偏向片段级检索，较少提供显式因果联系和时间组织的长时情景记忆" |
| 不是性能竞争系统 | §7/§8.10："主要验证机制层面的可运行性与可解释性，而非在大规模复杂任务上的性能优势" |
| 不是规则引擎 | §1.2/§8.7：弱中心控制，行为由激活分布塑造而非显式规则调度 |

## 五、哪些原则不可违背（不可让渡清单）

按"违背即不再是 FAS"的标准排序：

1. **统一表示（万物皆图）**：知识、经历、情绪、目标、倾向、能力、参数都以节点/边/权重存在于同一图中，认知状态 = 激活分布的整体形态。外部 Python 状态对象承载认知状态即违背。（§3, §8.3）
2. **激活扩散是主驱动力**：注意、联想、候选行为、行动选择都应可解释为激活传播与竞争的结果，而非 if-else 分支。（§5, §8.5）
3. **弱中心控制**：不允许存在一个显式调度器决定"接下来该认知什么"。管线可以有固定顺序，但**行为内容的选择**必须来自动力学。（§2.3.2, §8.7）
4. **行动选择 = 注意竞争的延续**：回答、提问、沉默、搜索、记录应当是同一场竞争中的候选，而不是由代码分支裁决。（§8.5）
5. **LLM = 受约束的结构归纳器**：LLM 输出结构（事件框架/三元组/分类/参数），图结构规则检验后写入；LLM 不在隐式空间中做长期记忆、状态跟踪与决策。（§8.8.1）
6. **事件框架组织情景记忆**：经历以事件枢纽节点+论元槽位+时间锚+父子链条入图，而非扁平边或文本日志。（§3.2-3.4）
7. **学习内生**：边权/激活/结构在认知过程中持续更新（Hebbian 共激活、重复验证增强、结果回写），不存在"先跑后学"的两阶段。（§6）
8. **情绪与性格是动力学调制因素**：情绪调制扩散参数，性格是长期稳定的调制偏置——两者都应改变系统"如何扩散"，而不是改变 prompt 里的说话风格。（§1.2, §3.3）
9. **过程可追溯**：每个行为输出都能回溯到激活路径与图结构变化；这是区别于黑箱 LLM 的立身之本。（§8.6）
10. **诚实的能力边界意识**：论文反复强调"当前只验证了机制可运行性"；发育阶段协议（Development Companion 终将退出核心推理流程）要求能力真实、不虚构。（§8.10, capability_registry）

### 违背的判定标准（用于后续审计）

一个机制 X 是否违背原始愿景，问三个问题：

- Q1：X 的决策权在图动力学，还是在代码分支/LLM 隐式判断？
- Q2：X 的状态存在图里，还是图外的 Python 对象/文件里？
- Q3：删掉 X 后，行为差异能否由激活扩散+结构差异解释？若能，X 是冗余的流程拐杖。

## 附：论文预言已经应验的失败模式

论文 §8.9 预警了三种失败模式，2026-08 的现状全部命中：

| 论文预警 | 当前应验 |
|----------|----------|
| 高连接度枢纽节点 → 激活过度集中，系统长期偏向高频概念 | 用户/Fascinator/LLM回答/社交互动 是超级枢纽；`inter_decay_floor=0.5` 的大地板正是对这种噪声的对抗性补丁 |
| 边权更新缺约束 → 路径锁定，削弱探索 | Hebbian 强化（§6.2）从未实现，反而由 disposition/review 路径做离散大幅改权（±0.05~0.12），且无连续弱化通道 |
| 情绪/动机调制参数 → 非平稳性，需上下界/平滑/异常检测 | 参数调制机制整体未实现（config 是静态 dict，不在图上），预警暂时空转——但 V2 若落地参数节点，必须带上这条约束 |

这组对应关系说明：**原始论文对系统的理解深度超过后续工程实现**。重评估应以论文为基准系，而不是以现状为基准系。
