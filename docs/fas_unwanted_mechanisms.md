# FAS 非预期机制排查（fas_unwanted_mechanisms.md）

> 认知架构重评估 · 文档 4/7
> 回答重评估提纲问题 (5)：哪些机制应该删除？
> 排查对象（用户点名的九类）：硬编码行为 / 为 LLM 便利造的复合节点 / 图外状态 / 图变成流程控制器 / 聊天机器人包装 / if-else 行为决策 / demo 式智能 / 破坏自然激活竞争的机制 / 阻止人格形成的固定规则 / 让所有输入产生机械回复的机制。
> **原则：不要因为某机制"已经实现"就默认它必须保留。** 反之亦然：不因为"看起来聪明"就保留。
> 每条给判定（删除/降格/改造）+ 代码证据（file:line）+ 删除后行为如何由动力学接管的说明。

## §1 硬编码内容与规则（最严重类别）

### 1.1 app.py 启动时硬编码注入真实用户知识（删除）

**证据**：app.py:374-408。`_taught_nodes`（奶茶/饮料/挖矿/连锁挖矿模组/连锁采集/卓越前线/银矿/通用机械/铀矿，9 节点带 `taught_by_user: True`）+ `_taught_edges`（9 条）。注释明说"来源: 用户关于 Minecraft 模组和饮料的分享"。

**为什么 unwanted**：这些是**真实用户的真实教学经历**，本应由事件框架经记忆巩固通路入图（喝奶茶 已迁移为事件就是明证，见 402 行注释）。把它们写死在源代码等于：
1. 宣告"知识也可以不走巩固通路"——巩固机制的存在感被掏空；
2. FAS 的"记忆"变成部分伪造：它没经历过"学习奶茶"这个事件，却"记得"奶茶；
3. 换一台机器部署，FAS 带着别人的记忆出生。

**删除后动力学接管**：这些知识已存在于 data/runtime_graph.json（启动注入是幂等的）。正确动作是把它们导出为一个 knowledge pack（`user_teaching_2026-07`），从源代码移除。taught_by_user 属性保留，作为边来源证据。

### 1.2 CURIOSITY_CHAIN 15 条硬编码好奇链边（删除）

**证据**：curiosity_engine.py 顶部 DECLARATIVE/PROCEDURAL 词表 + 15 条固定 chain 边（12 条 trigger_curiosity 组成"未知→知识缺口→好奇→生成→等待"剧本链，3 条 resolve 收尾边）。

**为什么 unwanted**：这是把"好奇心应该如何发展"**预先写成剧本**。好奇的方向本应由图结构决定（未知=低邻域/低置信），链条边让系统只能按剧本好奇。用户判定 Q3：删掉后，未知检测（UnknownObject、稀疏邻域、FAISS miss）依然驱动 CuriosityDrive——好奇行为不消失，只是不再按剧本走。

**删除后动力学接管**：好奇对象 = 激活到达但邻域稀疏的节点（论文 §6.1 稀疏检测 + 已有 UnknownObject 联动，见 emergent §2.4）。共激活自然强化（Hebbian，P1 补实现）会让"用户常聊的方向"自动成为高好奇方向——好奇倾向从经历中长出来，替代剧本。

### 1.3 意图判定的正则硬编码（降格为兜底，决策权移交）

**证据**：app.py 内 `_ctrl_directive`（`停止.{0,4}话题|换个话题|换话题吧|别问了|打住|到此为止|不想聊这个`）、`_search_intent`（`搜一下|搜搜|搜索|上网搜|网上搜|网上查|查一下|查查|帮我查|search`）、`_tech_unknown`（`[A-Za-z0-9]…` 图外概念判定）。

**为什么 unwanted**：三类判定都是行为决策（要不要停/要不要搜/算不算未知），却用字符串正则裁决。LLM 四层分类（dialogue_act 等）每轮都在跑，本可承担，但正则**先于** LLM 判定并短路它——决策权被最粗糙的工具占据。且正则只匹配特定措辞（"换话题吧"能过，"聊点别的"漏掉），脆弱。

**改造**：dialogue_act=meta_conversation 类（NLP_PARSE 示例 7 已有先例：元对话指令输出空 nodes）→ _ctrl_directive 降级为 LLM 失败时的兜底。搜索意图由 未知信号+期待+倾向 竞争决定（见 §7），正则仅作零成本预筛。

### 1.4 关键词表标注器（降格）

**证据**：disposition_store.py:85-145。`_EMPATHY_MARKERS`（13 词）、`_NEGATIVE_MARKERS`（14 词）、`_POSITIVE_MARKERS`（11 词）+ 长度阈值 → classify_behavior / classify_outcome。

**为什么 unwanted**：这是**阻止人格形成的固定规则**的直接实例。人格形成通路（情境→行为→结果→边权）的奖赏信号完全来自 38 个关键词——词表外的反馈全部失明（用户说"这段有点意思"不算正反馈，说"烦死了但是你继续问吧"算纯负反馈）。FAS 的"性格"将永远长成 38 个词的形状。

**改造**（不删除通路，升级信号源）：优先级=图内情绪节点共振（情绪已入图，且是结构化信号）> embedding 话题延续（BGE 已在用，替换 bigram jaccard）> 词表兜底。详见 refactoring plan P1。

## §2 图被用作流程橡皮图章（决策先于图，图只追认）

### 2.1 搜索后强制 +3.0 激活（删除）

**证据**：app.py:1857-1900 区域。代码**先**用正则决定搜索，执行 do_web_search，**然后**给 网络搜索 节点 +3.0 激活。注释写"万物皆图"。

**为什么 unwanted**：激活是裁决的**依据**，不是裁决的**回执**。先决策后注激活，图只是把代码的决定抄写一遍——这是对万物皆图的字面服从与实质背叛。论文 §8.5："行动选择在结构上被视为注意竞争的延续"——顺序反了就什么都不是。

**删除后动力学接管**：未知信号（UnknownObject 激活、稀疏邻域、FAISS 无命中）→ 未知信息 节点激活 → 未知信息-触发→网络搜索 边（已存在，app.py:333）→ 网络搜索 与 LLM回答 竞争。意图词作为输入侧的额外激活注入（模拟"用户明说的愿望"），不是代码分支。

### 2.2 强制通过阈值的豁免通道（删除）

**证据**：app.py 回答判定处——存在 web_results 时 LLM回答 无视 θ_action 强制生成；好奇心问题直接替代回答（app.py:2038 注释"如果本轮触发了好奇心，则抑制普通 LLM 回答"）；沉默判定中 response_expectation 豁免条件。

**为什么 unwanted**：每次豁免都是一条 if-else 叠加在竞争裁决之上。豁免清单会无限增长（每遇到一个 case 加一条），最终竞争只剩形式。这正是"图变成流程控制脚本"的过程性描述：**不是一次设计错误，而是每次补丁都在把竞争裁决替换成豁免规则**。

**删除后动力学接管**：搜索结果作为激活注入（结果文本的实体命中节点+网络搜索节点本身带结果完成度），好奇问题作为高激活的 行为:追问 候选参与竞争，response_expectation 转化为 行为:回应 的初始激活增益。所有豁免变成激活权重，竞争裁决不变。

### 2.3 两阶段扩散的 config 体操（删除）

**证据**：app.py:1795-1838。好奇心触发时临时改 `config["max_depth"]=3` 跑 3 步、恢复、再跑剩余步数。

**为什么 unwanted**：流程控制借道 config 对动力学做直接干预。补丁惯例化后（emergent §3.3），任何"需要分阶段扩散"的需求都会复制这个模式。

**改造**：扩散引擎提供显式多阶段 API（`diffuse(inject_a, steps=3)` → 注入 B → `diffuse(steps=rest)`）。行为不变，机制诚实。

## §3 认知状态活在图外（万物皆图违规）

### 3.1 `_current_curiosity` module 级 dict（删除）

**证据**：curiosity_engine.py 模块级 `_current_curiosity` dict 保存活跃好奇问题（问题文本、目标节点、轮次计数），resolve 靠它判定。

**为什么 unwanted**：这是全系统最典型的图外认知状态——"FAS 此刻好奇什么"是核心认知状态，却活在 Python 模块变量里。重启即失忆；图内好奇心节点与这个 dict 是两套真相。

**改造**：活跃好奇问题=好奇心节点（cognitive 空间，带 问题文本/目标/提出轮次 属性）。它的激活值就是"还好奇吗"的答案；扩散衰减自然实现"好奇随时间冷却"；回答命中目标节点时 resolve 由图查询完成。

### 3.2 episodic buffer 的 Python 对象（降格为草稿队列，长期归还图）

**证据**：episodic_buffer.py 全部——容量 100 的内存 List，承载记忆草稿/表达事件/倾向证据三重职责，晋升判定在 Python。

**为什么 unwanted**：论文 §4.1 的缓冲器是"多模态对齐整合中枢"，窗口由图内参数调节；实现成了完全图外的三合一队列。工作记忆在 FAS 里的本义是**激活分布**（论文 §8.2："短时注意状态直接依附于长期知识拓扑"），另设一个 Python 工作记忆等于架构自我否定。

**改造**：短期保留为记忆草稿暂存（输入→LLM 抽取之间的瞬时容器，无跨轮状态）；倾向证据队列迁入 disposition pair 的 evidence 字段（已有）；晋升判定并入统一巩固通路（audit §2.4）。

### 3.3 capability_registry 的 JSON 双轨（合一）

**证据**：capability_registry.py：data/capability_registry.json 为主存储，图内 能力_ 节点为同步副本。

**为什么 unwanted**：同一认知状态两个真相源。图内镜像存在恰恰证明图表示是够用的——JSON 只是先入为主。

**改造**：图为主（能力_ 节点+驱动关系边），JSON 降为缓存或删除。

### 3.4 vision ObjectMemory（P1 整理）

**证据**：vision_processor.py 内 ObjectMemory 维护对象识别历史（图外 dict）。

**改造**：对象识别历史=对象节点的访问时间戳与识别置信度属性（图内已有节点，加属性即可）。

### 3.5 self_model 把用户建模进自我模型（拆分）

**证据**：self_model.py `_extract_self_candidates`：把 用户→X 的边当作 FAS 偏好候选、用户是X 当作信念候选（社交类降权 ×0.6 但不排除）。

**为什么 unwanted**：自我模型的定义性特征是**第一人称**。"用户喜欢奶茶"进 FAS 的 偏好: 节点，等于 FAS 认为自己喜欢奶茶——自我模型与用户模型混淆。这不是理论洁癖：反思引擎会据此产出"FAS 喜欢X"的虚假自我认知。

**改造**：self_model 只接受 Fascinator→X / Self→X 证据；用户模型（用户是X、用户喜欢X）本就以用户节点为中心存在于语义图，无需复制——需要"对用户的认知"时查图即可（共享实体耦合本来就是论文 §3.4 的设计）。

## §4 流程触发边：基础设施节点间的固定管道（删除）

**证据**：app.py:329-335。启动时固定创建 4 条边：

```
社交互动 -[触发 0.85]→ LLM回答
需要确认 -[触发 0.7]→ 社交互动   （注释：情绪 → 社交 → LLM回答 通路）
未知信息 -[触发 0.8]→ 网络搜索
网络搜索 -[辅助 0.8]→ LLM回答
```

**为什么 unwanted**：这 4 条边就是写在图上的流程图。它们的存在使"竞争"变成摆设：社交输入注入社交互动节点后，激活**必然**沿 0.85 的固定边流到 LLM回答——不是 LLM回答在竞争中胜出，而是管道通到了那里。需求确认-触发→社交互动 更是把"情绪应该引向社交回应"这个认知假设固化成了永久管道。

**删除后动力学接管**：行为节点（回应/追问/沉默/搜索/记录）各自在图内，情境/情绪/未知节点的激活沿**习得的**边（Hebbian 由共激活自然强化）流向行为节点。最初系统确实会"不知道社交输入该干嘛"——这正是发育阶段协议的本义：允许早期行为由 disposition candidate 的低强度边驱动，随经历强化。

## §5 聊天机器人包装（把认知系统演成聊天产品）

### 5.1 FAS_IDENTITY 人设钉死（降格）

**证据**：prompt_templates.py:21-30。所有 prompt 以"你是 Fascinator……你通过激活扩散机制进行联想和推理"开头；ANSWER_GENERATE 附加"不存在预设的说话风格"。

**为什么 unwanted**：身份陈述本身没错（诚实），但它承担了本应由图承担的职能——"我是谁"应从 Self 子图与经历中长出（Self-喜欢→X、行为倾向、能力清单都在图里），prompt 只是图状态的**转译器**。当前 prompt 是静态的：无论 FAS 经历了什么，"它是谁"的描述永远一样，这直接对抗"人格从经历中形成"。

**改造**：prompt 保留最小身份常量（名字+语言接口定位），动态部分（当前活跃倾向、近期情绪、能力边界）由图状态生成注入——FAS_IDENTITY 从"人设卡"变成"自我状态的快照"。

### 5.2 response_expectation 作沉默豁免（竞争化，见 §2.2）

期待度是语用信号，应转化为 行为:回应 的初始激活增益，不是 if-else 豁免条款。

### 5.3 机械礼貌/复读风险（由竞争解决）

**证据**：110 轮 chat_log 中多次"好，我们换个话题。最近有什么想聊的吗？"式模板化回应——无倾向可用时代码兜底产生了千篇一律的社交句。

**为什么 unwanted**：这是"让所有输入产生机械回复的机制"的直接来源：兜底句是硬编码的，兜底被触发的频率越高，FAS 越像复读机。

**改造**：删除兜底句生成；竞争无胜者时允许真沉默（行为:沉默 本来就是词表成员）。沉默比假话更符合诚实原则。

## §6 三套互不相通的行为候选系统（统一）

**证据**：
1. NLP_PARSE 的 `suggested_reply_goals`（14 种，LLM 产出，answer_question 消费）；
2. disposition_store 的 `BEHAVIORS`（9 种，强化学习消费）；
3. action_engine 的 `COGNITIVE_CAPABILITIES`（4 种，requirements 检查）。

**为什么 unwanted**：同一认知职能（"下一步做什么"）有三套表示、三套判定、互不引用。reply_goals 每轮由 LLM 生成后**即弃**（不入图、不积累），disposition 缓慢积累但不驱动回复（只注入文本暗示），capabilities 决策结果只回显不执行。三者并存使任何一个都无法达到阈值效应——这是"人格形成 9 天零产出"的架构原因之一。

**改造**：统一为图内行为节点（沿用 BEHAVIORS 9 词表起步），reply_goals 降级为行为节点的**激活信号**（LLM 提名的意图→对应行为节点获得激活），disposition 边提供**习得偏置**，θ_action 裁决。capabilities 退役，能力清单并入能力注册表。

## §7 上游注入与下游裁决绕过竞争（V2 主攻方向）

散落在 §2 各条之外的同类问题汇总——它们共同构成"激活竞争名存实亡"的现状：

| 注入侧（给谁多少激活） | 裁决侧（谁赢了） | 应有形态 |
|---|---|---|
| 社交输入→社交互动节点固定注入 | 0.85 固定边直通 LLM回答 | 情境节点激活→习得边→多行为竞争 |
| 搜索判定=正则→事后 +3.0 | web_results 存在即强制生成 | 未知信号注入→竞争 |
| 好奇问题=module dict 状态 | 直接替代回答文本 | 行为:追问 节点竞争 |
| response_expectation=prompt 字段 | 沉默判定豁免条款 | 行为:回应 激活增益 |
| INFRA_IDS 每轮过滤 infra 节点 | infra 永不参与竞争 | 基础设施节点区分对待而非一刀切 |

**为什么单列**：单独修任何一条都会被下一条抵消。竞争裁决的恢复必须**一次性整体**完成（V2 核心），否则豁免通道永远能借道绕行。

## §8 demo 式智能（表面能力，无认知基础）

**证据**：
1. `_taught_nodes`（§1.1）——FAS 一开机就"精通"Minecraft 模组，因为它**被编程为**精通，演示效果好，认知上虚假；
2. `_alias_patches`（app.py:356-359）——Minecraft/Fascinator 的别名手写死在启动代码（机制本身泛化了，清单该进 pack）；
3. 能力注册表初始化注册 ~24 项能力——多数是"接口存在"而非"能力可用"（SocialDrive 等三个 drive 是空 stub 也注册了）。诚实条款（只注册真实的）被"看起来全面发展"的愿望侵蚀。

**判定**：全部按 pack 化/机制化/诚实化处理。demo 式智能的统一特征：**能力与经历脱钩**。FAS 的每个可展示能力都应能回答"你是怎么学会的"——答案必须是一条可追溯的经历/激活路径，否则该能力的展示就是在演。

## §9 失效的门控（看似存在，实际放行一切）

**证据**：app.py 记忆提取门控——`_non_teaching_das` 设计意图是"非教学类对话行为不触发知识抽取"，但 dialogue_act 不在列表时的 fallback（几乎一切输入都有 dialogue_act 兜底）使门控形同虚设；数据佐证：458 节点中 回答记录 52 + 思考 22，而 disposition 产出 0——图在大量吸收对话流水，几乎不产出结构化认知增量。

**为什么 unwanted**：门控失效不是安全问题而是**学习质量问题**：无条件抽取让"每个输入都值得记"成为默认，巩固机制失去选择性——而选择性恰是记忆巩固的认知意义（什么值得记是认知判断，不是记录义务）。

**改造**：抽取触发由图信号决定（情绪显著/重要性评分过阈/未知概念/显式教学），dialogue_act 仅作特征之一。配合 P1 的重复验证 δ 增强（audit §2.4），让"反复出现的才巩固"。
