## 统计与结论风险

- **C 的统计结论**:P1-E 后 C 应不变;若 C 退化 → 说明负极性泛化
  越界,回滚 P1-E(回滚 = 移除 ingest 的失败分支,单点)。
- **论文已冻结数字**:所有修复在战役层且带开关 → 已发表的
  capability_gap_v2 数字可标注"pre-repair assembly"保持有效;
  修复后数据作为新实验轮报告,不混入。
- **P1-F 的双通道冗余**:自主层 goal registry 与 self-graph
  current_goal 并存 → 可能双计目标压力。缓解:consumer 只做
  激活注入,不改 registry;论文注明双通道关系为开放问题。

## 回滚设计

| 提案 | 回滚方式 |
|---|---|
| P0-a | 还原截断常数(1 行) |
| P1-E | 移除 ingest 失败分支(≤10 行,单文件);或加装配开关 eventframe_in_context=True/False(推荐,默认 False 保持现役) |
| P1-F | consumer 为独立函数+单调用点;移除即回滚;生产侧若实施,加 config 开关(默认现役行为) |

## 结论

P0 两项零风险。P1-E 风险可控且方向单一(必须配 C/K 阴性对照)。
P1-F 是唯一触及生产语义的提案 → 按 §13 保持 patch proposal,
实施前需作者裁定语义意图,并接受"architecture change"标注与
E+C 联合测量的义务。
